# Testudio++

Расширение для VS Code, которое показывает тесты проекта на CMake в панели Testing, запускает их и позволяет создавать и править кейсы с входными данными прямо в редакторе.

## Зачем это нужно

В лабораторных по основам программирования тесты бывают двух видов:

- кейсы данных: папка с аргументами, входными файлами и ожидаемым выводом, как в `tests/testdata/` первой лабораторной;
- обычные тесты на C++ (gtest), которые собираются через CMake и запускаются командой `ctest`, как во второй лабораторной.

Раньше приходилось запускать всё из терминала, а кейсы создавать и править руками, следя за пробелами и переводами строк. Testudio++ собирает оба вида тестов в одном дереве и берёт на себя рутину с кейсами.

## Возможности

1. **Дерево тестов в панели Testing.** Группа «Кейсы testdata» показывает кейсы по папкам, группа «Тесты C++» показывает тесты ctest по наборам gtest. Запустить можно всё сразу, группу или один тест, у каждого теста виден статус. Бледная галочка рядом с тестом это результат прошлого сеанса: VS Code хранит результаты между запусками, а плагин сам тесты при открытии не запускает. Карточка такого кейса пишет «Нет результата в этом сеансе». Прошлые галочки убирает кнопка «Clear All Results» в заголовке панели Testing.
2. **Карточка кейса.** В отдельной вкладке показаны имя, статус, код возврата, аргументы, входные файлы, а также ожидаемый и фактический вывод рядом.
3. **Diff.** Если кейс упал, кнопка «Diff» открывает встроенное сравнение ожидаемого и фактического вывода.
4. **Создание и правка кейса.** Форма в той же карточке: имя, аргументы по одному на строку, входные файлы и ожидаемый вывод. Имя и обязательные файлы проверяются до записи на диск. Когда карточка переходит в режим правки, её вкладка закрепляется, и клик по другому кейсу в дереве форму не заменяет.
5. **Принять фактический вывод.** Если программа выдаёт верный результат, а эталон устарел, одна кнопка заменяет `expected.txt` фактическим выводом (после подтверждения).
6. **Удаление и переименование кейса.** Удаление спрашивает подтверждение в отдельном окне, новое имя проверяется по тем же правилам, что и при создании. Кейс можно удалить и прямо из дерева: кнопка с корзиной в строке кейса или пункт «Удалить кейс» в правом клике. Подтверждение то же, а открытая карточка этого кейса закрывается.
7. **Показ двоичных и особых файлов.** Нулевые байты, символы `\r` и байты вне UTF-8 в карточке видны как `\0`, `\r` и `\xNN`, а не пропадают.
8. **Сборка проекта.** Команда «Testudio++: Собрать проект» запускает `cmake --build` для каталога сборки, после успеха дерево обновляется. Оно обновляется само и тогда, когда ctest получает новый список тестов после пересборки: плагин следит за файлами `CTestTestfile.cmake`, `*_tests.cmake` и `*_include.cmake` в каталоге сборки.

## Формат кейса

Кейс это папка внутри `tests/testdata/`. Имя начинается с номера, например `04_OnlyNewlines`. В папке лежат:

- `args.txt`: аргументы запуска программы, по одному на строке;
- `expected.txt`: ожидаемый вывод программы;
- любые входные файлы, которые программа читает.

В `args.txt` и `expected.txt` строка `{dir}` означает путь к папке кейса. Перед запуском плагин заменяет её на настоящий путь, поэтому кейс не привязан к конкретному компьютеру.

Пример, кейс `04_OnlyNewlines` (во входном файле три пустые строки):

```text
tests/testdata/04_OnlyNewlines/
  args.txt
  expected.txt
  input.txt
```

Содержимое `args.txt`:

```text
{dir}/input.txt
```

Содержимое `expected.txt`:

```text
3 0 3 {dir}/input.txt
```

Кейс считается пройденным, если программа завершилась с кодом 0 и её вывод побайтово совпал с `expected.txt` (после подстановки `{dir}`). Запускается программа без оболочки, с пустым вводом, в корне открытой папки. Если она не уложилась в таймаут, процесс убивается и кейс считается упавшим.

Папка без `args.txt` или `expected.txt`, а также папка с недопустимым именем остаётся в дереве с серой пометкой причины, остальные кейсы при этом работают. Такой кейс открывается кликом, а удалить его можно из карточки или из правого клика.

## Требования

- VS Code версии 1.100 или новее;
- CMake и ctest в `PATH` (нужны для группы «Тесты C++» и для команды сборки; кейсы данных работают и без них);
- macOS или Linux.

## Установка

Из готового файла `.vsix`:

```bash
code --install-extension testudio-0.1.0.vsix
```

Из исходников:

```bash
git clone https://github.com/wFeeL/Testudio.git
cd Testudio
npm install
npm run compile
```

После этого откройте папку Testudio в VS Code и нажмите F5: откроется второе окно с подключённым расширением. Файл `.vsix` собирается командой:

```bash
npx vsce package
```

Расширение включается само, когда в открытой папке есть `CMakeLists.txt`.

## Настройки

Настройки лежат в разделе «Testudio++» (Settings), ключи начинаются с `testudio.`.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `testudio.testdataPath` | `tests/testdata` | каталог с кейсами относительно корня открытой папки |
| `testudio.buildDirectory` | `build` | каталог сборки для `ctest` и `cmake --build` |
| `testudio.executablePath` | не задан | тестируемая программа; если путь не задан или файла нет, при первом запуске кейса откроется выбор файла, путь запомнится в настройках рабочей области |
| `testudio.timeoutSeconds` | `10` | таймаут запуска одного теста в секундах |

## Как пользоваться

1. Откройте папку проекта с `CMakeLists.txt` и соберите проект (`cmake -S . -B build`). Настройку сборки плагин не делает, это остаётся за вами.
2. Откройте панель Testing. Появятся группы «Кейсы testdata» и «Тесты C++».
3. Если проект изменился, выполните в палитре команд (Ctrl+Shift+P или Cmd+Shift+P) «Testudio++: Собрать проект». Результат сборки смотрите в выводе «Testudio++».
4. Запустите тесты кнопкой запуска у нужного пункта. Для первого кейса плагин попросит выбрать тестируемую программу, например `WordCount`. Выбранный путь проверяется: если это папка, несуществующий файл или файл без права на запуск, плагин объяснит причину и предложит выбрать другой файл.
5. Откройте карточку кейса: кликните по кейсу в дереве (если в VS Code включён двойной клик в списках, кликните дважды). Повторный клик показывает уже открытую вкладку, а не создаёт новую. Карточку открывают также кнопка «Открыть карточку» в строке кейса и пункт того же названия в правом клике. В палитре команд тот же пункт предлагает выбрать кейс из списка.
6. В карточке доступны кнопки «Запустить», «Diff», «Принять фактический вывод», «Изменить», «Переименовать» и «Удалить».
7. Чтобы создать кейс, нажмите правой кнопкой на группу «Кейсы testdata» и выберите «Новый кейс» (или одноимённую команду в палитре). Новому кейсу подставляется следующий номер, например `32_`.
8. Чтобы сменить тестируемую программу после первого выбора, выполните в палитре команд «Testudio++: Выбрать тестируемую программу». Выбранный путь запоминается в настройках рабочей области (`testudio.executablePath`).

В форме имя может состоять из латинских букв, цифр и подчёркивания, пустой аргумент не допускается, имена `args.txt` и `expected.txt` для входных файлов заняты. Если проверка не прошла, текст ошибки показывается в форме, а на диск ничего не пишется.

## Ограничения

- Windows не проверялся, работа гарантируется только на macOS и Linux.
- Править в форме можно только обычный текст: корректный UTF-8 без нулевых байтов и без `\r`. Двоичные файлы, файлы с `\r` и очень большие файлы (больше 100000 байт) показываются с пометкой «двоичный или с \r, правка недоступна» и при сохранении остаются прежними.
- Тесты на C++ плагин только показывает и запускает. Править их нужно в самом коде, плагин этого не делает.
- Проект плагин не собирает перед запуском тестов и не меняет `CMakeLists.txt`.
- Если открытая форма правки кейса не закрыта, а файлы кейса изменили руками, сохранение формы перезапишет эти изменения.
